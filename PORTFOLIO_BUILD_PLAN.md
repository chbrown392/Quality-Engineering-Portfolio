# Portfolio Build Plan — Complete Scope

## 1. Career positioning
- Primary target: QA Lead / QA Manager / Senior Salesforce QA leadership.
- Secondary target: enterprise manual QA leadership and quality-process ownership.
- Differentiator: build and govern quality systems, not only execute test cases.
- Avoid: presenting as an automation engineer, developer, or test-framework specialist.

## 2. Audience
1. Recruiters — fast proof of role fit.
2. Hiring managers — evidence of process maturity and Salesforce depth.
3. Engineering/Delivery leaders — evidence of governance, risk thinking, and cross-functional leadership.
4. Interview panels — shareable case studies for structured discussion.

## 5. Flagship case studies
1. Enterprise QA Lifecycle Transformation
2. Salesforce Flow Fault-Handling Validation
3. Automated Case Management and Scheduled Closure
4. Requirements Clarification: Correct Record/File Association
5. Turning Business Requests into Testable Acceptance Criteria

Each uses: Context → Challenge → Role → Approach → Test Strategy → Result → What It Demonstrates.

## 6. Design system
- Visual tone: enterprise, technical, understated, credible.
- Background: deep navy/charcoal.
- Accent: cyan/blue with restrained green for quality indicators.
- Typography: system sans; no specialty font dependency.
- Cards: 14–18 px radii, thin borders, subtle shadows.
- Layout: 1200 px max-width; strong whitespace; mobile-first breakpoint support.
- Motion: subtle reveal only; never distract from content.

## 7. Accessibility
- Semantic headings.
- Keyboard-accessible navigation.
- Visible focus states.
- Skip-to-content link.
- High-contrast text.
- Reduced-motion support.
- Descriptive link text.
- No essential information conveyed by color alone.

## 8. SEO / recruiter discoverability
- Title and meta description around Salesforce QA leadership.
- Open Graph metadata.
- Structured, descriptive headings.
- Case-study pages with unique titles/descriptions.
- Custom domain when ready.

## 9. Publication safety
Run every item through `PRIVACY_SANITIZATION_CHECKLIST.md`. Replace employer-specific identifiers with neutral equivalents unless the information is already public and you intentionally want it disclosed.

## 10. Launch sequence
1. Review content accuracy.
2. Add public contact links.
3. Publish GitHub repository.
4. Enable GitHub Pages as technical mirror/evidence hub.
5. Create Framer project.
6. Connect Framer Agent to Claude Code/Codex.
7. Use `CLAUDE_FRAMER_AGENT_PROMPT.md` to build the visual site.
8. QA desktop/tablet/mobile.
9. Validate every outbound link.
10. Connect custom domain.
11. Add portfolio URL to LinkedIn, resume, applications, and recruiter messages.

## 11. Ongoing maintenance
- Add one sanitized case study for each meaningful leadership problem solved.
- Keep resume and certification references current.
- Review public content quarterly for stale claims.
- Never use production screenshots unless explicitly approved for public release.
